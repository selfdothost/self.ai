## Async Kubernetes client — the GPU-lease force-reap capability
# (selfai_ui/utils/vram_k8s.py, self.ai!202/R5) uses it to delete a stale
# consumer's pod via core's mounted ServiceAccount. THIS is the file the image
# actually installs (Dockerfile: `uv pip install -r requirements-api.txt`).
# Deliberately version-agnostic: the reaper's 401 was NOT a version bug but a
# `uv pip install` corruption — uv produced a mixed-version tree whose
# incluster_config.py writes the SA token under api_key['authorization'] while
# configuration.py's auth_settings() reads api_key['BearerToken'], so
# auth_settings() returned {} and the client sent no Authorization header (401
# on every real reap; the token itself was valid — curl with it = 200). The
# Dockerfile force-reinstalls this package with pip (clean, single-version) and
# asserts the real load_incluster_config()->auth_settings() path yields a bearer
# header at build time, so a corrupt/mismatched install can't ship. See
# self.ai!210/!212, selfinfra#166.
kubernetes_asyncio>=35.0.0
